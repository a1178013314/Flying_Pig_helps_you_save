# 账本维护规则

账本 = [docs/LEDGER.md](../../docs/LEDGER.md)，记录**当前现状**，不记录历史。它是本仓库唯一的进度事实源。

## 读写时机

- **开工先读**：任何涉及实现或进度判断的任务，先读账本，再动代码。账本里的「接下来做什么」第一条通常就是本次该做的事，但**必须以用户本次明确要求为准**，不一致时以用户为准并把差异记进账本。
- **收工必写**：本次会话结束前（交付了任何代码/文档改动之后），更新账本。没交付东西的会话不用更新。
- **重写覆盖，不追加**：三段内容每次重算，旧状态靠 `git log` 追溯，账本文件本身不留历史。

## 三段结构（固定，不得增删段）

| 段 | 写什么 | 硬约束 |
|---|---|---|
| **本次做什么** | 本会话实际承担的事项 | 最多 3 项；每项必须有**完成标准**——能当场验证的那句话 |
| **已完成** | 已交付且仍在起作用的东西 | 每行必须带**落地位置**（文件路径 / 命令 / commit）与**验证方式**。写不出位置 = 没完成，放回「本次做什么」 |
| **接下来做什么** | 后续待办，按优先级排 | 每行标**阻塞项**与**归属**（对应总纲 §7 里程碑或 §8 风险编号）。本段第一条 = 下次会话的「本次做什么」 |

## 状态只有四个值

`待做` / `进行中` / `已完成` / `阻塞`。用这四个词，不自造（"大致完成""差不多了"这类表述禁止出现）。

## 编号复用，不新造

引用总纲已有的编号：里程碑 `D1`–`D4`、阶段 `S0`–`S6`、风险 `R1`–`R13`、组件名 `gateway`/`orchestrator`/`ingest`/`agent-runner`/`renderer`/`packager`，术语以 [CONTEXT.md](../../CONTEXT.md) 为准。账本不引入新的 ID 体系。

## 数字只引用

时间、并发、体积、质量阈值等口径一律引用总纲 §5，账本内不得另立数值（口径唯一事实源原则）。

## 头部三行必须同步

`更新时间`、`当前阶段`、`一句话现状` 每次更新时一并改写。「一句话现状」要让没读过其他文档的人一眼知道项目卡在哪。
