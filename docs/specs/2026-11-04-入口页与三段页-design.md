# 入口页与三段页设计（飞猪帮你省）

- 日期：2026-11-04
- 范围：移动 Web 的两张页——入口页（原样还原飞猪首页）与三段页（省心 / 省钱 / 省时间），含路由、导航、数据接线、资产、标注、验收
- 不在范围：replan/refresh 性能与密钥口径（批次 B）、ECS 部署（批次 C）、真实推送通道、多航线管理、登录
- 上游：`docs/需求.md` §一/§五、`PRODUCT.md`、`.impeccable/surfaces/web-src-routes-save.md`（三段页方向契约）、`docs/原型/功能页-三段页（已选）.png`（780×1688）、`docs/入口页面，这个要原样实现.jpg`（1080×2400）、`docs/specs/2026-11-04-数据管道-design.md`（数据与接口）
- 一句话：两页一个 spec，因为三段页的三条未决项（tab 怎么对齐、tab 合并、刷新范围）必须由入口页的形状来定；数据层已就绪，这批只做前端与一处后端语义修正。

## 0. 批次划分（账本 7 项的合并结论）

| 批次 | 含账本哪几项 | 合并理由 | 状态 |
|---|---|---|---|

| B | ②replan 超时降次 + ③refresh 提速 + ③'`BAILIAN_API_KEY` + ④'`FLYAI_API_KEY` | ②③改同一处预算与提示词；③'④'改同一处 env 与体验模式行为；且 replan 的火车候选缺失正是缺 key，共用一条验收线 | 待做 |

## 1. 决策清单（自问自答，已定）

| # | 问题 | 结论 | 理由 |
|---|---|---|---|
| 1 | 两页怎么分 | 入口页一条路由、三段页一条路由 | 三段页是"做事"页，入口页是"逛街"页；塞一层会把三件事挤成信息流 |
| 2 | 路径 | `/` = 入口页；`/save?seg=money\|heart\|time` = 三段页，缺省 `money` | 段状态进 URL，刷新与回退都可预期 |
| 3 | 入口页怎么进三段页 | banner 位换成"飞猪帮你省"三功能入口卡（内容本来就是我们要设计的）；类目「机票」直达省钱 | 原截图 banner 内容无绑定，是唯一可承载我们功能的位置 |
| 4 | 其余图标/搜索栏/券包/底 tab | 纯视觉，不可点 | 六个假 tab、五个假券都是"原样"的代价，做成可点就是撒谎 |
| 5 | 底 tab 5 项 | 按截图原样（淘/视频/消息/购物车/我的淘宝），用 `div` 不用 `button` | 不可点的东西不能长得像按钮，也不该进 tab 顺序 |
| 6 | 假状态栏（4:47 / 5G） | 不画 | 浏览器自己有；画一个假状态栏只会和真状态栏打架 |
| 7 | "原样"到哪一格 | 结构级：板块顺序、栅格列数、字号层级、色值、圆角对齐截图；重建为真组件 | 用户已选；像素拼贴改一个数字就要重切图 |
| 8 | 图从哪来 | 从截图裁切为本地 PNG 资产，落 `apps/web/src/assets/home/`，provenance 记 `docs/DESIGN.md` | 不引外链图、不找新素材，出处唯一 |
| 9 | 入口页文案与数字 | 全部编造，集中 `apps/web/src/pages/entry/seed.ts` | 改内容不动布局；也满足"数据是编的"这条硬约束 |
| 10 | 省钱段曲线画什么 | 画 `dataset.watch.series`：出发日起连续 5 天的同航线最低价；轴标 5 个日期；卡内一行小字「曲线是同航线按日最低价」 | 没有价格历史数据源；这是唯一有数又有"目标虚线"几何关系的线 |
| 11 | 目标价存哪 | 只存 `localStorage`：`flypig:target:<transport_no>`；后端 `watch.target_price` 恒 0，界面不读 | 后端刷新会整份重写 watch，存进去会被冲掉；单用户单实例够用（shortcut：多端同步时挪回后端） |
| 12 | "什么时候推我" chips | 多选，存 `localStorage`：`flypig:push:<transport_no>`；卡下小字「示例期内只记录偏好，不发通知」 | 没有推送通道，不假装有 |
| 13 | 推送记录 | 只渲染 `dataset.watch.push_log`（后端观测到的变动），空态一句话 | 后端已按 series 对比自动记；模型给的 push_log 一律不信 |
| 14 | 省心输入 | 单个 textarea（≤200 字，与后端 `@Length(1,200)` 对齐）+ 3 个快捷 chip 追加文本（带娃生病 / 航班取消 / 临时有事） | 可组合的 chip 组合器要状态机，成本远大于收益；一段话本来就能说清 |
| 15 | 省心结果落哪 | 只在本次会话渲染，刷新即失（replan 不落库）；无结果时展示快照 `interruption` 示例场景 | 后端契约如此；要落库得改契约，不在这批 |
| 16 | 省时间怎么换航线 | 一次只跟一条航线；换航线 = `POST /discover` → 取最低价那条 → `POST /watch` → `POST /dataset/refresh` → 回读 `/api/dataset`；界面先明说"会替换省钱段盯的班次" | 快照只有一份 watch（术语表：不得分段各存一份）；全部复用现有接口 |
| 17 | `cheapest-days` 航线不匹配时 | 后端改为只回 `{days:[]}`，不再起一次"刷新旧航线"的任务 | 现有分支返回的 jobId 永远补不出查询航线的数据，是误导 |
| 18 | 轮询 | 抽出 `pollJob(jobId, {timeoutMs: 620_000, intervalMs: 1000, onStage})`，两页共用 | 现面板 150s 上限小于执行器 300s×2 轮，是真 bug |
| 19 | 组件库 | 不加 shadcn（未装，也不必要），沿用 tailwind + 现有 token，`index.css` 补 3 个色值 | 两页只用卡片/胶囊/输入/按钮四种件 |
| 20 | 临时验证面板 | 删除 `apps/web/src/pages/home.tsx`，由两页取代 | 面板与三段页功能重复，留着会分叉 |
| 21 | 测试边界 | 只对非平凡逻辑写 vitest（最便宜那天、目标价读写、轮询超时、换航线前置校验）；页面靠 §10 的 8 条人工验收 | 页面结构测试收益低，断链风险靠验收拦 |

## 2. 路由与导航

```
/                     入口页（长页，无底部 bar 的交互，5 项 tab 纯视觉）
  ├─ 类目「机票」        → /save?seg=money
  └─ 三功能入口卡        → /save?seg=money | heart | time
/save?seg=…           三段页（顶部返回箭头 → /）
```

- 返回：三段页品牌行左侧加 36px 圆形返回键（原型没有，窄屏浏览器没有可靠返回手势，必须给）。
- `seg` 由 URL 决定，切段 = `navigate(..., {replace: false})`，浏览器返回键回到上一段而不是直接跳出页面。

## 4. 三段页外壳

```
┌ 品牌行：[←] 飞猪帮你省            [示例数据 · 一键更新]
├ 分段控件：省心(红点) / 省钱 / 省时间        ← 三选一，白卡浮起
├ 状态提示行：正在盯 1 个航班 · 3 分钟前更新 / 这一条航线还没有数据
├ 当前段内容（§5–§7）
└ 底部按钮区（省钱：调目标价 / 再盯一个航班）
```

- 「示例数据 · 一键更新」= `POST /api/dataset/refresh` → 轮询 → 回读 `/api/dataset`；三段共享一份快照，所以**一次刷新刷全部**（这也是原未决项之一：全刷）。
- 卡片右下角固定一行 11px 来源小字，三种取值：
  - `flyai 实查 · 更新于 MM-DD HH:mm`
  - `示例种子 · 未实查`（`meta.source === "seed"`）
  - 追加 `· 体验模式：非机票价打码`（`meta.mode === "trial"`）
- 省心段红点：有未读的 replan 结果时亮，进入省心段即灭（本地会话状态，不持久化）。

## 5. 省钱段

**输入行**：一个输入框，占位「输入航班号，例如 MU5101」+ 橙色「加盯」。

**加盯流程**（全部走现成接口）：

```
POST /api/discover {flight_no}         → need? 显示反问并要求补城市/日期，停
                                       → offers[]? 取价格最低一条
POST /api/watch {origin,destination,date,transport_no}
POST /api/dataset/refresh              → 轮询（stage 上屏）
GET  /api/dataset                      → 卡片上屏
```

**卡片**（对齐原型）：

- 头：班次号 22px/700 + 「盯着」绿胶囊；第二行 `11.06 周四 09:05 · 首都 T2 → 虹桥 T2`
- 价格行：现价 `¥490`（34px/700/橙，`tabular-nums`）+「现价起」；右侧「目标价 / ¥420 / 还差 ¥48」
- 目标价未设：右侧显示「设目标价」按钮，点了就地输入（正整数），存 localStorage
- 曲线：SVG polyline，318×104，`series` 5 点归一化；目标虚线在设了目标价时出现；当前点实心圆，最低点空心圆
- 轴：5 个日期 `MM.DD`，出发日标「出发」（落地时改：`watch.date` 不一定是今天，标「今天」会说谎）
- delta 文案：`未来 5 天最低 ¥250（11.09），比你目标低 ¥170` / 未设目标时 `未来 5 天最低 ¥250（11.09）`
- 现价缺失（`offers` 为空）：价格位显示 `—`，文案「还没有查到这条班次的报价，点右上角更新」

**什么时候推我**：3 chips（降价就推 / 每天 9:00 / 起飞前 6 小时），多选，localStorage，卡下小字说明不真发通知。

**推送记录**：`push_log` 倒序，每行 `MM-DD HH:mm · ¥490 → ¥468`；空态「还没观测到价格变动」。

**底部按钮**：「调目标价」（聚焦目标价输入）、「再盯一个航班」（聚焦输入行）。

## 6. 省心段

- 行程卡（只读）：`快照里记录的被打断行程`：班次、日期、时刻。「换一条被打断的行程」不在本批（见 §12）。
- 输入：textarea，`maxLength=200`，占位「例如：MU5101 取消了，我 11-06 下午 3 点前必须到上海」；下方 3 个快捷 chip 追加典型场景文本，可叠加。
- 提交：`POST /api/replan {situation}` → 轮询（stage 直接显示，例如「正在查 11-07 的票」）
- 结果：
  - `done` → summary 一句 + ≤3 条候选（kind / 班次 / 起降时刻 / 价格 / note / 跳转链接）
  - `need` → 显示反问与原话，回到输入态，不清空已输入内容
  - `failed` → 红字错误 + 「重试」按钮（重试就是再提交一次，服务端会复用同一 jobId 规则不变）
- 空态：展示快照 `interruption` 的 2–3 条示例候选，标注「示例场景」，提示「说一句你的情况，我重新排」。

## 7. 省时间段

- 输入：开始城市 + 目的地（默认取快照 `watch` 的城市对）+ 「算」。
- 与快照航线一致：`GET /api/cheapest-days?origin&destination` → 5 天条形/列表，最便宜那天橙底高亮，结论句 `11.09 走最便宜，¥250，比 11.06 少 ¥200`。
- 与快照航线不一致：
  1. 先给一句明确代价：「一次只跟一条航线，换航线会替换省钱段盯的班次」
  2. 用户确认后：`POST /discover {origin,destination,date=明天}` → 取最低价 → `POST /watch` → `POST /dataset/refresh` → 轮询 → 回读 `/api/dataset` → 渲染 5 天
  3. discover 回 `need` 或多条班次都拿不到价 → 原样显示原因，不自动重试
- 空态：`days` 为空且航线一致 → 「还没有这条航线的数据」+ 「让智能体去查（约 3 分钟）」按钮（同上流程）。
