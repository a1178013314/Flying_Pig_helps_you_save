# 数据管道与智能体执行设计（飞猪帮你省）

- 日期：2026-11-04（v5：管道代码已实现并跑通真实链路，本节按实测校正 v4 的猜测）
- 范围：三个功能的数据从哪来、agent 怎么跑、产物怎么验、存哪、怎么刷新
- 不在范围：入口页复刻、三段页视觉、真实推送通道、部署
- 上游：`docs/需求.md` §三（运行时 = opencode CLI）、`docs/specs/2026-11-04-初始架构-design.md`（骨架）
- 一句话：所有数据查询与判断都由 opencode 完成，后端只负责给它一个带围栏的沙箱、一个提示词、和一道不许撒谎的闸门。

## 0. 执行模型

```
用户动作 → 后端建执行目录（opencode.json + skill 副本）
        → spawn: opencode run --dir <jobDir> "<任务提示词>"
        → opencode 自己调 flyai（只能调它，别的一律拒绝）
        → 它把结果写进 jobDir/dataset.json 与 raw/*.json
        → 后端过三道闸门 → 通过才写快照 → 前端轮询拿结果
```

agent 负责"怎么查、查几次、怎么选"，后端负责"给它什么权限、它交的东西能不能信"。这条边界是本次设计的核心。

### 0.1 数据源已知边界（2026-11-04 实测，agent 也无能为力的部分）

| 类别 | 事实 | 对产品的约束 |
|---|---|---|
| 能拿 | 机票（航线+日期，10 条，价格精确）、国际航线、火车、酒店、门票、商品；全部单行 JSON | 三个功能的数据底座成立 |
| 拿不到 | 价格历史、航班动态（延误/取消）、退改签政策、余票、机型行李、天气 | 曲线只画未来；中断场景是我们设定的；不许写"可免费改签""仅剩 3 张" |
| 条数上限 | 所有命令只回 10 条，无分页 | 不做"全网最低"承诺；低价排序下前 10 条够用 |
| 航班号不可直接查 | `--transport-no` 必填起降城市且实测返回 `status:1`；`ai-search` 也查不到 | 允许 agent 回 `need` 反问（决策 12），而不是硬报错 |
| 区间查询非按天覆盖 | `--dep-date-start/end` 只回 10 条、按价格全局排序 | 5 天必须逐天查（写进 refresh 提示词） |
| 体验模式 | 非机票价格打码为 `¥2xx`，附「体验模式」提示 | 有 agent 也无法绕过；key 缺失时界面必须标注 |

### 0.2 端到端实测结论（2026-11-04，`bailian/qwen3.8-flash`）

已跑通：opencode 加载项目内 `.opencode/skills/flyai/SKILL.md` → 自己调 `flyai search-flight` → 把原始 stdout 存 `raw/flight.json`（9350 字节）→ 写出 `offers.json`（MF8561 ¥490 / MU5186 ¥564 / CA1835 ¥620），三条价格全部能在 raw 里字符串命中，闸门 3 可过。

同时探到三个反例，写进§5与§12：`bash` 权限全 deny 会让 bash 工具从工具表里消失（agent 直接说「没有 shell」）；cherry-gateway 指向的 `127.0.0.1:23333` 未运行时所有请求 `ECONNREFUSED`；skill 文件在沙箱内可被 `edit` 改写（实测模型确实尝试过重写 SKILL.md）。

### 0.3 端到端实测（2026-11-04，管道代码 + 真实 opencode + 真实 flyai）

| 链路 | 结果 |
|---|---|
| discover 北京→上海 2026-11-06 | 约 50s 完成，10 条真实班次全部过三道闸门；价格 490–714，`jump_url` 均为 `router.feizhu.com` |
| refresh（同一航线） | 单轮 175s 完成：5 天逐天最低价 450 / 350 / 260 / 250 / 220，`mode` 被判 `trial`，`push_log` 由后端补 5 条，`interruption.candidates` 3 条 |
| agent 自陈 | `notes`：火车候选放弃——体验模式下 `search-train` 返回 `1xx/5xx` 打码价，raw 里没有可用数字，按「不许编造」不写。闸门与提示词的诚实约束在真实模型上生效 |
| 只给班次号 MU5101 | 7s 回 `{"need":["出发城市","到达城市","出发日期"],"question":"…"}`，前端追问一次即可 |
| replan（「MU5101 取消，要赶 11-06 下午 3 点的会」） | **未跑完**：单轮超过 300s 被强杀进入第二轮，累计 8 分钟仍在 running。原因在提示词范围——同时要求「同航线当天 + 次日 + 火车」，而体验模式下火车价全是 `1xx/56x` 打码值，闸门不许用无 raw 佐证的数字，模型就反复重查想拿一个可用价。修法见 §12，不在本次范围内换执行方案 |
| 关掉深度思考（`models.*.options.enable_thinking: false`） | 同一提示词走 opencode：`reasoning` 33 → 0 token、2448ms → 1145ms；真实 discover 50s → **21s**，真实 refresh 175s → **208s**（没变快：瓶颈是 8–10 次 flyai 串行调用，不是推理）。字段由模型级 `options` 透传进兼容端点请求体，实测确认生效 |
| 提示词叫它并发查 5 天 | 无改善（208s → 217s）：模型收到"并发"两个字但没有把它落成一次 shell 调用。要生效得给命令模板，见 §12 |
| 慢的真正构成（逐项计时） | flyai 单次真调用 **0.6s**（9346 字节）；opencode 冷启动含 `.opencode/node_modules` 安装 **1.7s**；一轮空转 **1.4s**，每轮固定重发约 10k token 上下文（input 780 + cache read 9216）；一次「查询 + 重定向落盘 + 回答」= **28s**。refresh 要 8–10 次查询 → 约 200s。**所以时间花在模型轮次与每轮 prefill 上，不在 flyai、不在深度思考** |
| 「手抄原始输出」的代价 | 不加"用重定向落盘"这句时，模型会把 9KB stdout 读进上下文再抄写，实测这条反而没写出文件、还转头去 `npm install`（19.4s 空转）。所以 §7 的 raw 落盘要求必须写明"重定向、不要读进上下文" |
| 阶段文案 | 轮询期间在动：`正在查 11-07 的票` → `正在查 11-06 的票` → `正在查 11-10 的票`，与逐天查询的实际节奏一致 |

## 1. 决策清单（自问自答，全部已定论）

| # | 问题 | 结论 | 理由 |
|---|---|---|---|
| 1 | 谁执行数据查询？ | opencode 全程 | 用户明确定的方案；agent 自己决定调用顺序与次数 |
| 2 | 后端还调不调 flyai？ | 不调 | 一旦后端也调，就出现两套逻辑、两套数据；执行权只留一个主人 |
| 3 | agent 怎么知道有 flyai？ | 仓库内 `.opencode/skills/flyai/SKILL.md`（官方 skill 的复制，MIT），每个 job 目录里再放一份 | opencode 认项目内 `.opencode/skills/`；复制进仓库才能跟着部署到 ECS |
| 4 | 怎么防止它乱跑命令？ | 每次 job 生成 `opencode.json`：`bash` 只放行 `flyai *`，其余 `deny`；`webfetch`/`websearch` `deny` | 不给它联网搜别处、不给它 rm/curl；`--auto` 只在这个已被限定的范围里生效 |
| 5 | 怎么防止它编造价格？ | 三道闸门（§6）：结构守卫 + 5 天齐全 + 每条价格必须在 `raw/*.json` 里出现过，且 `jump_url` 域名为 `router.feizhu.com` | 模型编不出 `router.feizhu.com` 的链接，也编不出 raw 里没有的价 |
| 6 | 它不写文件怎么办？ | 提示词要求产物落文件；没写 → 判失败重试一次 → 再失败 job failed，旧快照不动 | 不解析 stdout（那里混着日志与模型自言自语） |
| 7 | 一次跑多久？ | 关掉深度思考后实测：discover 21s（原先 50s）、refresh 208–217s、need 反问 7s；超时 300s | refresh 的上限是 flyai 单次 10–20s × 8–10 次调用，属 I/O 而非推理，见 §12 |
| 8 | 慢得能不能接受？ | 能，但要遮：任务态 + 阶段文案（「正在查 11-07 的票」）+ discover 结果缓存 10 分钟 + 进省钱段时后台预取 | 用户等 1 分钟要看得到在动 |
| 9 | 不可测怎么办？ | `AgentRunner` 接口 + 录制产物 fixture；闸门、解析、状态机全部单测；agent 本体只做手动验收 | 别假装有集成测试 |
| 10 | 失败了给什么？ | 旧快照 + 人话错误（「缺 11-08 的报价」「有 2 个价格在原始输出里找不到」）+ 重试按钮 | 失败原因要能指导下一轮 prompt |
| 11 | 重试带不带上下文？ | 带。第二轮的 prompt 附上「上一轮缺 11-08、价格 ¥468 无来源」 | 同样的错不该犯两次 |
| 12 | 航班号能直接查吗？ | 不能（flyai 无此能力）。所以允许 agent 回 `{ need: [...], question: "..." }`，前端追问一次 | 全 agent 的好处就是它可以反问，而不是硬报错 |
| 13 | 要不要多轮对话？ | 不要。一次动作一个独立会话，不 `--continue` | 省 token、可复现；追问靠显式的 `need` 字段而不是对话记忆 |
| 14 | 模型？ | `bailian/qwen3.8-flash`（参赛要求），走百炼兼容端点，key 从 `BAILIAN_API_KEY` 注入，**模型级 `options.enable_thinking: false` 关掉深度思考** | 2026-11-04 实测跑通整条链（见§0.2）；可覆盖 |
| 15 | 快照还是关系表？ | 整份快照，SQLite 单表固定一行 | 形状会变，关系表是负担 |
| 16 | 断网/模型挂？ | 退回 `source: "seed"` 的种子快照，界面改标「示例数据」 | 演示不能白屏，但也不能假装是真价 |
| 17 | 用户在等的时候能点别的段吗？ | 能。job 是后台的，前端只轮询自己关心那个 | 一段在跑不该锁死整页 |
| 18 | 并发点两次？ | 同类型 job 复用 running 的那一个，返回同一 jobId | 两个 agent 同时写一份快照必然互相覆盖 |

## 2. 执行目录与产物协议

```
<jobDir>/                          /tmp/flypig-agent/<jobId>/，跑完即删（失败保留供排查，7 天）
  opencode.json                    本次运行的限制（模型、skill 路径、permission）
  .opencode/skills/flyai/SKILL.md  从仓库复制
  input.json                     本轮任务输入：{type, task, previous}，previous 是上一轮快照
  raw/                             每次 flyai 调用的原始 stdout，文件名 agent 自取
  dataset.json   |  offers.json  |  plan.json    任务产物（三种任务各交一种）
```

`input.json` 是 v5 补的：决策 13 定了「不开多轮会话」，那 agent 唯一的上下文来源就是这个文件——盯的航线、目标价、被打断的行程、上一轮快照都在里面读，不靠对话记忆。

`raw/` 是信任的根：没有 raw 佐证的任何数字都不许进快照。

## 3. 数据契约

放 `packages/shared/src/dataset.ts`，前后端同源。`parseDataset(json: unknown): Dataset` 手写守卫（不引 zod）。

| 块 | 字段 | 说明 |
|---|---|---|
| `meta` | `source: "flyai" \| "seed"` / `mode: "live" \| "trial"` / `updated_at` | 后两项由后端覆盖，不信任模型给的时间 |
| `watch` | `origin` / `destination` / `date` / `transport_no` / `target_price` / `offers[]` / `series[{date, price}]` / `push_log[{at, from, to}]` | 省钱段：选定的航班 + 未来 5 天该航线最低价 + 变动记录。`push_log` 由后端比对新旧 `series` 追加，agent 一律交空数组（它看不到历史） |
| `offers[]` | `id` / `transport_no` / `airline` / `journey_type` / `dep_city` / `dep_station` / `dep_time` / `arr_city` / `arr_station` / `arr_time` / `duration_min` / `price` / `jump_url` | flyai 行程归一化后界面要用的字段 |
| `interruption` | `flight{transport_no, origin, destination, date, dep_time}` / `reason` / `candidates[{kind, transport_no, dep_time, arr_time, price, jump_url, note}]` | 省心段的设定场景 + 1–3 条替代（同航线改签 / 次日 / 火车） |
| `notes` | 可选字符串 | agent 说明「为什么这块是空的」（实测：体验模式下火车票价打码，它据此放弃候选） |

省时间段不进快照，但也不必再问一次模型：刷新任务本来就把未来 5 天逐天查过一遍，`watch.series` 就是答案。`GET /api/cheapest-days?origin&destination` 因此从快照派生——航线匹配就返回 `{ days[5] }` 并缓存 10 分钟；航线不匹配返回 `{ days: [], jobId }`，后台起一次 refresh，前端下次再拿。v4 写的「触发一次 discover job」是错的：discover 只查一天，凑不出 5 天。

## 4. 接口

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| GET | `/api/dataset` | — | 200 Dataset |
| POST | `/api/discover` | `{ origin?, destination?, date?, flight_no? }`（可只给班次号，缺的让 agent 反问） | 202 `{ jobId }` → result `{ offers[] }` 或 `{ need, question }` |
| POST | `/api/watch` | `{ origin, destination, date, transport_no }` | 200 `{ watch }` 新骨架：`offers` / `series` / `push_log` 清空、`target_price` 归零，不查价，随后触发 refresh |
| POST | `/api/dataset/refresh` | — | 202 `{ jobId }`；已有 running → 同一 jobId |
| GET | `/api/cheapest-days` | `?origin=…&destination=…` | 200 `{ days[5] }`；航线不匹配时 `{ days: [], jobId }`，10 分钟缓存 |
| POST | `/api/replan` | `{ situation: string }`（1–200 字） | 202 `{ jobId }` → result `{ candidates, summary }` 或 `{ need, question }` |
| GET | `/api/jobs/:id` | — | `{ id, type, status, stage, startedAt, finishedAt?, error?, result? }` |

状态机：`queued → running → done | failed`；`stage` 是给人看的一句话（「正在查 11-08 的票」），由 runner 从 CLI 进度事件里取最近一条，取不到就写「智能体正在执行」。

## 5. 每个 job 的 opencode.json

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "bailian/qwen3.8-flash",
  "provider": {
    "bailian": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "bailian",
      "options": {
        "baseURL": "https://maas.qianwenaiapi.com/compatible-mode/v1",
        "apiKey": "{env:BAILIAN_API_KEY}"
      },
      "models": {
        "qwen3.8-flash": {
          "name": "Qwen3.8 Flash",
          "options": { "enable_thinking": false }
        }
      }
    }
  },
  "permission": {
    "bash": { "curl *": "deny", "wget *": "deny", "ssh *": "deny", "sudo *": "deny", "rm -rf *": "deny", "*": "allow" },
    "edit": "allow",
    "read": "allow",
    "webfetch": "deny",
    "websearch": "deny",
    "external_directory": "deny",
    "skill": { "flyai": "allow" }
  }
}
```

启动参数：`opencode run --dir <jobDir> --auto "<prompt>"`。`--auto` 的官方语义是「未被显式 deny 的权限自动放行」，实测确认它不会把执行卡在授权等待上（discover 50s、need 反问 7s 都是无人值守跑完的）。

`flyai` 不在全局：v5 把 `@fly-ai/flyai-cli@1.0.16` 装成 `apps/admin` 依赖，runner 的 `agentEnv()` 把 `apps/admin/node_modules/.bin` 前置进 PATH，实测真实调用出真价。

三条实测修正（2026-11-04，不是猜的）：

1. **`bash` 不能写 `"*": "deny"`**——会把 bash 工具从工具表里抹掉，agent 拿不到 shell 就只能空手交差。只能做「默认 allow + 高危命令 deny」，真正的护栏是一次性目录与 `external_directory: deny`。
2. **cherry-gateway 不可用**：它指向 `127.0.0.1:23333`，网关未开时所有请求 `ECONNREFUSED`；不依赖它，统一走百炼兼容端点。
3. **skill 文件可被改写**：模型实测会试图重写 `SKILL.md`。skill 副本写入后 `chmod 444`，落库前比对 hash，变了就判失败（v5 落地在 `JobsService`：每轮 `prepareJobDir` 返回 hash，runner 跑完立刻比）。
4. **只读副本会让下一轮 EACCES**：`chmod 444` 之后再往同一路径 `copyFileSync` 会 permission denied，所以每轮执行前必须 `rmSync(jobDir)`；测试里复用固定目录名时也要先删。
5. **官方 SKILL.md 正文是 flyai-cli 仓库 README**（构建与隐私说明），没有参数表；实测模型靠 `flyai --help` 自己摸出参数并跑通，因此保持逐字节复制、不改写。

## 6. 三道闸门（后端，写死在 runner 之后）

1. **结构**：产物文件存在 → `JSON.parse` → `parseDataset` / `parseOffers` / `parsePlan` 守卫；
2. **完整**：`series` 必须齐 5 天且每天 `price > 0`；缺任何一天 → 失败，错误写清缺哪几天；
3. **有据**：产物里每一个 `price` 必须能在 `raw/*.json` 的文本里找到（按固定 2 位小数比对），且每条 `jump_url` 的 host 必须是 `router.feizhu.com`。任一条不满足 → 记为「编造嫌疑」，失败。

实现签名 `runGates(jobDir, kind)`，`kind ∈ dataset | offers | plan`，由 job 类型映射（discover→offers、refresh→dataset、replan→plan）。返回三态：通过（带产物）/ 反问（`{need, question}` 原样透传，不算失败）/ 拒绝（带人话错误）。

三道都过才写快照。`meta.updated_at` / `mode` 由后端覆盖；`mode: "trial"` 由 raw 里是否出现「体验模式」字样判定——实测真实 raw 命中该字样，快照落成 `trial`。`push_log` 不由 agent 写：后端比对新旧 `series` 追加，保留最近 20 条。

## 7. 三类任务的提示词契约

- 公共纪律抽在 `prompts/common.ts`（raw 规则 / 不许编造 / 反问出口 / offer 字段表），三类提示词只写差异；只说清楚"要什么形状的文件、写到哪、raw 必须存原始 stdout"；不教它 flyai 参数（那是 skill 的事）；不许编、不许估算、查不到就写空数组并在 `notes` 里说明；
- `discover`：查指定航线指定日期的直飞班次，价格升序取前 10，写 `offers.json`；航线或日期缺了就写明「未提供」并要求交 `need`，不许猜（实测只给班次号 7s 回反问）；
- `refresh`：按已有 `watch` 查 ① 该班次当日报价 ② 该航线未来 5 天**每天各查一次**的最低价 ③ 省心段候选（同航线其他班次 / 次日 / 火车），写 `dataset.json`；
- `replan`：按被打断的行程 + 用户情况原文，查替代方案，写 `plan.json`，候选 ≤3 条且必须引用真实班次，不许承诺改签免费（flyai 无退改签数据）；
- 允许任何任务回 `{ "need": ["origin", ...], "question": "..." }` 表示信息不足。

## 9. 测试

测试共 95 条（`pnpm test` 全绿）：shared 18、admin 70（闸门 14 / registry 9 / 提示词 13 / runner 13 / pipeline e2e 17 / 骨架 4）、web 4、logger 3。

- 闸门单测：用真实录制 raw 做 fixture——合法产物通过；`price` 不在 raw 里 → 拒并写明条数；缺 11-08 → 拒；`jump_url` 域名不对 → 拒；raw 目录为空 → 全拒；`meta.updated_at` / `mode` 被后端覆盖（真实 raw 含「体验模式」→ trial，另一份把字样换掉的 fixture → live）；
- shared 守卫：`parseDataset` 拒三类坏数据（缺 `meta` / `series` 非数组 / `price` 为字符串），错误消息带字段路径；
- registry 单测：同类型 running 时返回同 jobId、终态后是新 job、终态不被阶段更新改写；
- runner 单测：执行目录形状（raw/、只读 skill 副本、opencode.json 的 model 与 permission、input.json）、skill hash 篡改可检出、成功即删 / 失败保留、7 天清理、PATH 里 flyai 可执行、缺 `BAILIAN_API_KEY` 直接给失败原因；
- e2e（Fake `AgentRunner`，闸门与状态机走真实代码）：refresh → done → 快照整份替换；闸门拒 → 旧快照不动；runner 抛错 → 旧快照不动；不交产物 → 重试一轮且第二轮提示词带上失败原因；skill 被改写 → 判失败；`need` 透传；同类型复用 jobId；watch 只写骨架；cheapest-days 命中缓存不起任务；
- 真实 opencode + flyai 只做手动验收（见 §0.3），耗时、token、稳定性都不适合 CI。

## 12. 风险与 shortcut

| 项 | 说明 |
|---|---|
| 白名单只能做黑名单 | `bash` 全 deny 会让工具消失，所以真正的护栏是「一次性目录 + 无 secrets + external_directory deny」，不是命令白名单 |
| skill 被改写 | skill 副本 `chmod 444` + 落库前比对 hash；模型已实测会试图改它 |
| 模型服务 | cherry-gateway 的本地网关依赖不可靠，统一走百炼兼容端点；`BAILIAN_API_KEY` 缺失则 job 直接失败而不是重试 |
| agent 不稳定 | 同一提示词两次结果可能不同；靠闸门兜住正确性，靠缓存兜住重复消耗 |
| 慢且贵 | 一次 refresh 8–10 次 CLI + 1 次模型；演示前预跑一次把结果缓存好 |
| `mode: "trial"` 判定靠字符串匹配 | raw 里出现「体验模式」即判 trial；官方改文案就失效，fixture 会先炸 |
| ECS 无 flyai / opencode | 线上刷新与重规划都会 failed；部署 spec 前置检查两者都能出结果 |
| shortcut | 内存 job 注册表与 10 分钟 discover 缓存：单实例可用，水平扩容换表/队列 |
| shortcut | jobDir 失败保留 7 天：`pruneStaleJobDirs()` 在 `JobsService.onModuleInit` 跑一次，进程常驻期间不再扫；长期不重启会攒目录 |
| shortcut | 阶段文案解析的是 CLI 默认文本输出里的最近一个日期，不是 `--format json` 的事件流；要按工具调用粒度显示阶段时换事件流 |
| 火车候选拿不到价 | 体验模式下 `search-train` 返回 `1xx/5xx` 打码价，raw 里没有可用数字 → 省心段的火车候选必然为空；注入 `FLYAI_API_KEY` 才可能有（实测 agent 自己在 `notes` 里交代了放弃原因） |
| 超时余量 | refresh 实测 208s，超时 300s 后只剩一次重试机会；再慢一档就得按类型分档（discover 短、refresh 长） |
| refresh 是轮次 bound | 单次 flyai 只 0.6s，8–10 次查询要 200s 是因为每次查询都要走若干轮模型往返、每轮重发约 10k token 上下文。三条杠杆，按性价比排序：① 提示词给死命令模板，把 5 天压进一次 shell（`for d in …; do flyai … > raw/$d.json & done; wait`），轮次从几十轮降到个位数；② SKILL.md 瘦身——正文是 flyai 仓库 README，构建与隐私段落对 agent 无用，却占每轮 prefill；③ 后端按 `(航线, 日期)` 缓存当天最低价，refresh 只补缺失的天。只喊"请并发"无效（已实测） |
| replan 范围过大 | 实测单轮 >300s 跑不完。下一步收窄：候选直接复用快照里的 `interruption.candidates`，只针对用户情况重排 + 最多补一次查询；火车在无 `FLYAI_API_KEY` 时明确不查（打码价过不了闸门），超时按类型分档 |
